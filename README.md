# Companion Kit

> 当前版本：`0.7.0-dev.1`。这一轮只把 Codex 体验做好；其他宿主保留已有能力和各自独立的 Persona，不在本轮扩展。

Companion Kit 想做一件很简单的事：让你常用的 Codex 里，多一个愿意陪你说话、也能把正事做好的对象。

你先在本地面板里说一句“我想认识一个什么样的人”。比如“高冷御姐，成熟、自信，解决问题利落”。面板会把这句话补成一份完整 Persona，你可以直接用，也可以慢慢改。之后打开 Codex 新任务，直接聊天、问问题或要一张照片，不需要先喊 Skill 名称，也不会先看到“能力已启动”之类的开场。

她不是另一个只能陪聊的机器人。写代码、查问题、整理资料和分析任务，仍然使用 Codex 原来的能力；Persona 只决定她怎样和你相处、怎样表达，以及照片中的人物是谁。

## 现在可以体验什么

| 能力 | 当前状态 |
| --- | --- |
| Codex 自然聊天 | 已接入 Plugin。新任务安静加载 Persona，不需要调用 Skill |
| 一句话创建 Persona | 已完成。模板只是可选起点，草稿可以预览、修改和再次补全 |
| Codex 原有任务能力 | 保留。技术正确性、安全和任务完成度始终优先 |
| 第一次确定长相 | 可以上传有权使用的成年人物/虚构形象参考，也可以描述后生成，或让 Persona 自己决定 |
| 固定人物照片 | 本地候选、确认和唯一参考链路已完成；真实 Codex 图片回执与参考图调用仍待跨机器验收 |
| Codex 生图 | 只用 Codex 内置 `gpt-image-2`，不需要 API Key，也没有 Provider 配置 |
| 关系状态 | 多维关系核心已完成；从真实聊天自动提取关系事件尚未接入 |

代码路径和本地测试已经覆盖 Persona 创建、当前任务图片回执、候选暂存、确认、跨任务取回及缺图时停止生成。这里的“完成”指本地契约和测试替身已经通过，不代表真实 Codex 生图端到端已经验收。不同 Codex 版本的图片工具名称、保存回执和参考图调用仍可能有差异，因此 `0.7.0-dev.1` 仍是开发者预览版。

## 五分钟开始

### 1. 下载

```bash
git clone https://github.com/BottleYo/companion-kit.git
cd companion-kit
```

需要 Python 3.11 或更高版本。Codex 聊天和生图都不需要单独设置 `OPENAI_API_KEY`。

### 2. 打开本地面板

```bash
python3 skills/virtual-companion/scripts/companionctl.py ui
```

面板只监听本机地址，并为每次启动生成新的随机访问令牌。

最短的设置过程只有三步：

1. 用一句话描述你想认识的人，或者点一个模板作为起点。
2. 看看自动补全的 Persona，改掉不喜欢的部分。
3. 保存，然后安装到 Codex。

不知道长什么样没关系，初始化时可以完全跳过形象确认。以后第一次要照片时再决定。

### 3. 信任一次 Codex Hook

Companion Kit 使用 Codex 官方 Hook。`SessionStart` 在新任务开始时读取本地 Persona；只匹配图片工具的 `PostToolUse` 在图片真正生成后记录一张短期、不透明回执，用来证明候选来自当前任务。Codex 不会自动信任新的命令 Hook；首次安装后，请按界面提示检查并信任它，也可以在支持的界面中用 `/hooks` 查看。

这些 Hook 不读取用户消息或聊天转录，也不保存聊天正文。图片回执只包含任务、路径和内容的哈希，不保存原始任务标识或绝对路径。Persona 上下文按优先级压缩到 3000 字符以内，任务质量、无 API Key、身份失败关闭和控制命令不会被长设定挤掉。配置不存在或暂时读不到时，Hook 会安静退出，不影响 Codex。

### 4. 新开一个任务，直接说话

不需要输入 `$virtual-companion`。可以直接说：

> 今天想随便聊聊。

也可以把事情交给她：

> 陪我看看这个项目为什么测试失败。

改过 Persona 后，新开一个任务即可重新加载。

### 命令行安装

不使用面板也可以安装：

```bash
python3 skills/virtual-companion/scripts/companionctl.py install --host codex
python3 skills/virtual-companion/scripts/companionctl.py install --host codex --apply
```

第一条只展示会改什么，第二条才真正安装 Plugin。

## Persona 不是一张性格标签

一份 Persona 会保存这些内容：

- 你怎样称呼她，以及你对这个人物最初的描述；
- 性格、说话方式、背景基调、重视的事和兴趣方向；
- 遇到正事时怎样协助你，以及明确的相处边界；
- 外观气质和照片默认风格；
- 是否已经确认脸部身份，以及当前关系投影。

模板只是省事的起点，不是角色列表。输入“高冷御姐”之类的描述时，面板会补齐一份彼此不冲突的草稿；用户亲手改过的字段会被标记并保留，再次补全时不会被默认值覆盖。人物面板可以随时回来调整。

初始化不会要求你一定先选一张脸。Persona 可以先成立，长相以后再定。

## 第一次照片怎样确定人物

第一次自然地说“拍张照片给我”时，如果还没有固定脸，人物会用简短、自然的话给出三个选择：

1. 上传一张你有权使用的成年人物或虚构形象参考；
2. 简单描述想要的感觉，让 Codex 生成候选；
3. 让她根据 Persona 自己决定一个候选。

无论从哪种方式开始，候选都会先展示给你。只有你明确说“就这张”“确认”或同等意思后，项目才会把它保存为当前 Persona 的唯一身份参考。确认之前，项目不会声称人物已经固定。

后续新任务会解析同一张私有参考图，并在私有上下文里要求 Codex 每次人物生图都把它作为参考。固定目标是脸部辨识特征和面部几何，不是发型、表情、妆容、衣服、姿势、场景或光线。这些内容应根据当下场景、关系边界和你的要求变化。

如果私有参考图损坏或无法读取，本次生图会暂停，不会退回纯文字提示再生成另一张脸。Runtime 也会要求 Codex 在成图后检查明显的人脸漂移；看起来已经是另一个人时，带同一参考重试或停止。这条行为仍要用真实图片工具调用验收。

需要说清楚的是：生成模型无法提供数学意义上的像素级身份保证。当前实现可以在本地保证只解析一份已确认参考、参考缺失时失败关闭，并把“使用参考、明显漂移时重试”作为高优先级任务规则。真实 Codex 图片工具是否在每次调用中接收并遵守参考，还需要端到端人工验收；在通过以前，项目不会宣传“完全不会换脸”。

## 为什么 Codex 不需要配置生图 Provider

Codex 路径只有一种：直接使用 Codex 自带的图片生成能力。

- 内置生图使用 `gpt-image-2`，计入现有 Codex 使用额度；
- 人物候选、日常照片和带参考图的后续生成都走这条路径；
- Companion Kit 不检查或索要 API Key，不展示 Provider、模型模式或额外付费确认；
- 图片能力不可用或额度耗尽时，只暂停本次照片，不影响聊天和解决问题。

这与“单独调用 OpenAI Image API”是两件事。API 适合编程式批量生成，但不属于 Companion Kit 在 Codex 里的日常路径。可参考官方的 [Codex 图片生成说明](https://learn.chatgpt.com/docs/image-generation)和[图片输入说明](https://learn.chatgpt.com/docs/image-inputs)。

## 人格不会拖低 coding 质量

新任务拿到的上下文里有一条明确的防火墙：代码正确性、测试、事实、安全和用户当前技术要求优先；Persona 只影响不关键的表达方式。

项目不会修改 Codex 全局“个性化”或“记忆”设置，也不依赖它们。你可以继续按自己的 coding 工作流配置 Codex，Companion Kit 只读取自己的本地 Persona。

## 关系不是一条升级进度条

关系同时保存三个长期维度：熟悉度、信任度和亲近度；短期气氛另行保存，并会随时间自然恢复。关系变化由少量、可解释的结构化事件驱动，还有幂等、冷却和每日上限，避免一条消息让关系突然跳级。

当前版本会在新任务中读取关系投影，并用它控制闲聊语气、主动程度和照片表达上限。但“从真实聊天判断并提交关系事件”的接线还没有完成，因此不会偷偷扫描关键词给亲密度加分。详见[关系状态规范](docs/RELATIONSHIP_SPEC.md)。

## Skill 为什么还在

Codex 日常聊天不依赖 Skill。`virtual-companion` 只保留为显式诊断入口，用来检查配置、图片状态和兼容能力；它不会在普通聊天中隐式启动。

正常体验来自 Plugin 的安静会话 Hook，所以项目不会输出“Skill 已启动”“正在加载人格”之类的聊天内容。Codex 界面自身显示的工作耗时和折叠工具轨迹属于宿主界面，项目无法隐藏，但人物回复里不会复述内部命令、路径、Provider 或处理状态。

## 每个宿主仍然是独立的

这轮只开发 Codex，没有把多宿主 Persona 合成一份。已经存在的 OpenClaw、Hermes、Claude 配置路径和适配仍保留；如果以后在同一台机器安装多个宿主，它们默认拥有各自独立的 Persona、关系和图片目录，不会因为人物同名就自动共享。

## 本地数据与隐私

公开仓库只包含程序、通用模板和文档，不包含任何用户的私人 Persona、聊天、记忆、人物照片、账号或凭据。

- Persona 默认保存在项目目录之外，并使用 Codex 独立命名空间；
- 关系库只保存结构化状态和事件，不保存聊天正文；
- 图片目录只保留一个候选槽和一张已确认身份参考，不形成照片图库；
- 只有当前任务图片工具回执中出现、且路径与内容哈希未变化的 PNG 才能进入候选槽；旧任务图片、被替换文件和重复回执都会拒绝；
- 候选 PNG 进入私有槽前会检查格式、尺寸、CRC 和实际解码结果，并移除文本、EXIF、GPS 等非必要元数据；
- 参考图路径只进入 Codex 的私有任务上下文，不向用户显示；
- 删除本地文件无法代替删除操作系统备份或宿主、Provider 侧可能存在的副本。

完整边界见[隐私说明](PRIVACY.md)、[数据生命周期](docs/DATA_LIFECYCLE.md)和[威胁模型](docs/THREAT_MODEL.md)。

## 开发与验证

```bash
PYTHONDONTWRITEBYTECODE=1 \
  PYTHONPATH=skills/virtual-companion/scripts \
  python3 -m unittest discover -s tests -v

PYTHONDONTWRITEBYTECODE=1 \
  python3 scripts/verify_public_bundle.py \
  --forbid-text '<你的私人角色名称>'
```

发布检查会扫描当前工作树和 Git 对象，拒绝人物媒体、聊天状态、数据库、密钥、符号链接、缓存、本机绝对路径和调用者指定的私人标识。
