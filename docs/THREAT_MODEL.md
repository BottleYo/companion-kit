# 本地核心与初始化面板威胁模型

## 保护对象

- 用户的人格配置与关系状态；
- 参考图、生成图和图片任务元数据；
- Provider 凭据及宿主认证；
- 当前任务或当前入站会话的投递目标；
- 公开发行包不含私人内容这一保证。

本项目主要防止误打包、越权读取、错误投递、浏览器跨站请求、符号链接重定向、低可信 Provider 降级和宿主重试导致的状态重复。它不承诺抵抗拥有同一用户权限的恶意本机进程、管理员、系统备份或第三方 Provider 自身。

## 信任边界

```text
浏览器面板 ──本次随机授权── 本地面板进程 ──结构化调用── 公共核心
宿主适配器 ──能力声明/当前目标── 公共核心
Codex ──内置生图── 当前任务图片
事件型宿主 ──最小图片请求── 用户配置的 Provider
本地状态库与资产库 ──明确导出/删除── 用户
```

人格表达层不处在宿主系统提示、安全策略或工具权限之上。网页、聊天和工具输出都是不可信输入，不能直接写关系数值、修改边界、选择 Provider 或改变投递目标。

## 当前已实现的控制

### 初始化面板

- 只监听 loopback 地址和随机空闲端口；
- 每次启动生成新的高熵授权值，关闭进程后失效；
- 授权值通过 URL fragment 交给当前标签页，读取后从地址栏清除，不进入查询参数和服务日志；
- API 校验 `Host`、写请求 `Origin`、授权头、内容类型和请求大小；
- 不启用 CORS，不提供目录浏览、任意路径读取或无确认覆盖；人物参考只接受浏览器文件选择器当次读取并转换的图片字节；
- 参考图上传要求本次面板授权、同源请求、格式与大小校验，以及成年和图片使用权确认；服务端再次清洗 PNG，上传后仍只是待确认候选；
- 配置文件和父目录遇到用户可控符号链接时拒绝。
- 配置保存使用私有跨进程文件锁，并在取得锁后重新读取版本，避免两个面板或 CLI 进程静默互相覆盖。
- 四个宿主默认使用各自配置路径；当前 Codex-first 面板只写 Codex Persona，拒绝提交宿主字段和任意路径，不会顺手修改其他宿主配置。

### 关系状态

- 模型只能提交候选事件；确定性归约器执行阈值、冷却、每日上限和分数边界；
- SQLite 事务、事件幂等 ID、忙等待、WAL 模式验证和版本化迁移避免重复更新或不兼容写入；
- 状态路径拒绝用户可控符号链接，目录和文件使用私有权限；
- 当前气氛按不透明会话作用域隔离并自动过期；
- 导出默认排除事件、来源标识、聊天、凭据和路径。

### 公开发行

- 顶层允许列表阻止临时文件进入发行输入；
- 工作树扫描拒绝私人状态目录、人物媒体、数据库、密钥文件、符号链接、缓存、常见绝对路径和疑似密钥值；
- Git 扫描覆盖可达与不可达的 blob、tree 路径、commit/tag 元数据与 ref，并拒绝 gitlink、嵌套仓库和用 replace ref 隐藏原对象；
- 已知私人角色标识必须在发布时通过可重复的 `--forbid-text` 规则加入扫描。

## Codex 内置图片控制

- Codex 人物原型、日常照片和参考图编辑只使用宿主内置图片能力；
- 不探测或读取 `OPENAI_API_KEY`，不向用户展示 Provider 选择，不创建额外 API 付费授权；
- 候选有两个受限入口：面板只接收用户当次选择并转换的 PNG 字节；Codex 聊天只接收当前任务图片工具回执中的 `CODEX_HOME/generated_images` 普通 PNG，回执绑定任务、工具调用、路径和内容哈希，单次消费并在两小时后过期；
- 当前 Codex 面板不读取其他宿主 Persona，也不检查 `OPENAI_API_KEY`；其他宿主诊断保留在显式 CLI/Skill 入口；
- 新任务通过 Persona 中的不透明主脸 ID 安全解析同一私有 Identity Pack；引用、身份版本、清单或任一已登记成员不一致时整包停止，不静默生成新脸；
- 主脸只锁定面部身份，体型补充只提供稳定体型特征；发型、表情、妆容、服饰、姿势和场景按本次需求变化；
- 内置图片不可用或额度耗尽时停止，不把独立 API 当作默认降级路线；
- 生成结果只返回当前 Codex 任务，不外发 IM。

## 严格图片与事件宿主控制

- Provider 状态探测、照片意图和付费授权分离；探测与 `prepare` 都不发起图片请求；
- 每次授权说明 API 计费、数据外发与虚构成年人边界，并绑定任务作用域、配置版本、提示摘要、参考图、固定路由和单次操作；
- 授权调用前先删除，只能消费一次；进程中断时宁可重新确认，也不自动重放可能已计费的请求；
- 凭据只读取当前进程环境，不进入配置、状态库、图片清单、导出、日志、Web 响应或错误正文；
- 严格执行器固定官方 HTTPS 端点、`gpt-image-2`、`high`、PNG 与单张输出，不接受自定义网关，不自动重试或降级；
- 参考图上传前严格校验，并重写为不含文本、EXIF/GPS 等附加元数据的 PNG；限制字节、像素、格式和数量；
- 资产目录拒绝符号链接并使用私有权限；配置只保存一个不透明参考 ID；
- 原型候选必须由用户再次确认才成为固定参考；严格模式不扫描或批量导入外部照片，也不得在未获授权时复刻真人身份；
- 生成与投递分开。严格成图只能由 OpenClaw / Hermes 当前入站会话接管，确认投递后清理；过期短期成图在后续启动时清理。
- OpenClaw / Hermes 的作业按宿主、安装实例、会话和首次事件摘要去重；后续付费确认可以来自新的事件编号，但不能跨实例或跨会话。
- 事件作业只保存摘要和不透明 ID；绝对路径只在最终宿主 handoff 边界展开，不保存联系人、chat ID 或 thread ID。
- handoff 只能成功一次。候选图先复制成会话绑定、路径唯一的短期快照，防止其他会话覆盖候选槽后改变已交付文件。没有明确宿主媒体回执时停在 `delivery_unknown`，禁止自动重发或报告已发送。
- OpenClaw 原生快速模式由宿主管理异步返回与补缺，Companion Kit 不叠加回调；Hermes 只通过当前响应 `MEDIA:` 指令交给 Gateway，不调用跨频道发送工具。

## 主要威胁与处理

| 威胁 | 处理 |
|---|---|
| 私人角色、聊天、照片或凭据混入发行包 | 允许列表、工作树扫描、Git 对象扫描、人工已知标识扫描 |
| 恶意网页请求本地面板 | loopback、随机授权、Host/Origin 校验、无 CORS、请求限额 |
| 配置或数据库路径通过链接写到别处 | 逐段拒绝用户可控符号链接，不接受任意面板路径 |
| 聊天提示注入直接加亲密度或放宽边界 | 候选事件协议、确定性归约、用户控制的恋爱开关和硬边界 |
| 宿主重试造成重复加分、重复付费或重复发图 | 关系事件使用幂等 ID 与事务；图片授权单次消费；事件作业首次事件去重且 handoff 单次 claim；API 和 Companion Kit 投递均不自动重试 |
| 图片路由暗中换模型 | 区分请求侧证明与响应侧回执；严格执行器固定官方端点、模型和画质，无合格路由即关闭 |
| 图片发错会话 | 事件作业绑定宿主、实例和会话摘要；最终适配器不接受任意目标；事件型与桌面型宿主分别限制返回范围 |
| 提示词、Key 或 Provider 错误泄露 | 授权只存摘要；Key 只读环境；错误不回显响应正文；陪伴消息不输出内部提示与状态 |
| 图片元数据或伪装格式进入本地资产 | 只接受 PNG，校验 CRC 与实际解码大小，保存前移除所有非像素必需分块 |
| Codex 被诱导把旧任务或任意本地照片设为人物 | 聊天入口只接受当前任务图片工具回执；面板入口不接收路径，只接收用户亲手选择并确认使用权的图片字节；两条入口都要再次明确确认 |
| Plugin 已安装但 Hook 未获信任，面板却误报可用 | 安装、用户审核进度、`SessionStart` 实际运行和 Persona/主脸加载分别建模；只有最小健康回执且当前资料早于该回执时才显示就绪 |
| 项目越过 Codex Hook 信任边界 | 面板只提供复制 `/hooks` 和用户进度确认，不读取或写入 `trusted_hash`，不使用绕过 Hook 信任的启动参数；Plugin/Hook 版本变化后旧回执失败关闭 |
| 临时成图长期残留 | 当前任务接管后显式清理；后续命令启动时清理超过一小时的短期成图 |
| 删除后仍有副本 | 只承诺产品控制范围；列出 WAL/SHM、缓存、备份和 Provider 留存边界 |
| 多宿主数据库冲突 | 默认独立；显式共享仅支持本机普通文件系统和相同 schema 版本 |

## 残余风险

- `quality=high` 只能证明请求值，不能保证审美结果或像素级人物一致；参考图编辑仍可能漂移。
- Codex 内置图片由宿主管理，项目不能独立证明单独的画质请求值；固定人物是否成立要通过参考图复用结果验收。不同 Codex 版本的图片工具名称、回执结构和原生保存位置仍需跨机器人工验证；匹配不到回执时固定流程会失败关闭。
- Persona 上下文限制为 3000 字符，低于 Hook 的 3200-token `additionalContextLimit`，并优先保留任务与身份规则；这降低但不能完全消除不同分词器下 Hook 大输出落盘的可能。
- OpenClaw 原生快速模式同样属于 `host_managed`；显式请求模型与画质不等于官方 API 直连证明。
- 图片生成完成到当前任务或会话真正接管附件之间存在短期本地文件；宿主不返回回执或任务永久中断时只能依靠后续启动清理。
- `delivery_unknown` 为避免重复发送而禁止自动重投，因此极端情况下可能实际未送达；这是“宁可不重复发，也不猜测发送结果”的取舍。
- 主脸资产晋升与人格配置引用跨两个文件边界，无法原子提交；能确认未绑定时会把严格匹配的单主脸还原为同一候选，提交结果不确定时则保留 Pack 与候选而不删除任何已绑定资产。进程崩溃或回滚文件系统故障仍可能留下孤儿。补充成员文件与 Pack 清单也存在极小崩溃窗口。孤儿资产不会被扫描或自动启用，但需要后续显式清理。
- 固定模型和同一 Identity Pack 也不能保证像素级人物一致；多角度成员只能提高稳定率，当前仍只能检测明显漂移并使用同一组参考重试或停止。
- 事件提取仍可能误判；当前阈值和限额只能限制影响，不能消除偏差。
- loopback 服务仍可能受本机恶意进程影响；高敏感部署需要操作系统级账户隔离。
- Git 对象扫描不覆盖尚未下载的远端 release asset、外部构建缓存或其他仓库，发布流程仍需单独核对这些位置。
