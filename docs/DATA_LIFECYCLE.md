# 数据生命周期与删除语义

## 数据分区

Companion Kit 把数据分成互不混装的几类：

| 类别 | 示例 | 默认位置 | 是否进入公开项目 |
|---|---|---|---|
| 公开程序 | 核心代码、文档、通用模板 | 项目目录 | 是 |
| 人格配置 | 称呼、通用特征、形象文字、关系开关 | 独立用户配置目录 | 否 |
| 关系状态 | 三个维度、结构化事件、短期气氛 | 独立本地 SQLite | 否 |
| 参考与生成资产 | 一个候选槽、轻量 Identity Pack、短期成图 | 当前宿主的 `private/images` | 否 |
| 用户恢复点 | Persona、关系库、候选与 Identity Pack 的一致性副本 | Codex 独立数据目录的 `backups` | 否 |
| 运行与升级系统数据 | 不含私人路径的安装收据、Hook 健康回执、审核进度和旧 Plugin 程序快照 | Codex 独立数据目录的 `system` | 否 |
| Codex 图片回执 | 当前任务、工具调用、文件路径与内容的哈希 | Codex 的 `private/codex-image-receipts` | 否 |
| 单次图片授权 | OpenClaw / Hermes 严格调用的任务、提示与配置摘要 | 对应宿主的 `private/authorizations` | 否 |
| 事件图片作业 | 当前会话与事件摘要、阶段、不透明 ID | OpenClaw / Hermes 的 `private/event-jobs` | 否 |
| Provider 凭据 | API key、宿主认证 | 宿主或系统凭据设施 | 否，项目也不保存 |
| 外部 Provider 副本 | 请求中上传的参考图与生成结果 | 第三方控制 | 不受本地删除控制 |

不保存完整聊天、联系人、工具参数、工具结果或完整图片提示词作为关系历史。结构化事件只保存事件类型、时间、增量、结果代码和不透明来源标识。

## 创建与更新

- 初始化只根据用户当次输入或通用模板创建新配置，不扫描现有宿主的人格、记忆、聊天或照片目录。
- Codex 使用根级默认命名空间；OpenClaw、Hermes 与 Claude 使用 `hosts/<host>/` 独立命名空间。当前 Web 面板只读取和写入 Codex；CLI 不自动跨宿主复制配置、关系、授权或图片。
- 配置默认写出 `schema_version = 3`；版本 1、2 仍可读取，但不会在只读时原地改写。下一次用户明确保存时才按当前 schema 写回。
- Persona v3 记录总意图、表达、背景、价值、兴趣、任务风格、动态外观默认值、可选脸部身份和字段来源。来源只区分“系统补全”与“用户修改”，不保存修改时的聊天原文。
- 关系状态数据库当前为 schema 2；打开 schema 1 时在单一事务中迁移宿主命名空间并保留状态，无法确认旧气氛来源时回滚并停止。发现更高版本时停止写入，不自动降级。
- SQLite 只支持本机普通文件系统。网络盘、共享盘和自动云同步目录不属于支持范围。
- 在支持 POSIX 权限的平台，关系目录收紧为仅当前用户访问，数据库文件为仅当前用户读写；路径经过用户可控符号链接时拒绝。
- 人格配置保存使用同目录私有锁文件协调多个本机进程；取得锁后重新校验版本，避免后写静默覆盖先写。
- OpenClaw / Hermes 图片授权只保存摘要，不保存任务原文或完整提示；默认十分钟过期，消费前先删除，避免进程自动重放付费请求。Codex 内置生图不创建这类授权。
- Web 面板的参考图只来自用户当次操作的文件选择器。浏览器限制格式与原文件大小，将图片缩放并重绘为 PNG；服务端要求面板临时授权、同源请求和图片使用权确认，再执行请求大小、PNG 结构、像素与解码上限校验。双方都不提交或接受用户原始文件路径。
- Codex 图片 `PostToolUse` Hook 只匹配图片工具。它从工具回执取得 `generated_images` 路径，保存任务、工具调用、路径、原始文件和清洗后像素的哈希；不保存原始任务标识或绝对路径。回执两小时过期，暂存候选时单次消费。
- `SessionStart` 成功运行后写入最小健康回执；`PostToolUse` 只在真实图片回执保存成功后写入自己的健康回执。单张健康回执只含 schema、Plugin 版本、Hook bundle 摘要、Hook 类型和最近成功时间，不含聊天、提示词、任务 ID 或参考图路径。
- 面板的“我已完成审核”只保存同一 bundle 下的用户操作进度与时间，不读取、写入或伪造 Codex 的 Hook 信任。Plugin 版本或 bundle 摘要变化后，审核进度和运行回执都自动视为过期。
- 事件作业按宿主、安装实例、当前会话和首次入站事件摘要去重；不保存联系人、chat ID、thread ID、聊天正文或绝对路径。默认保留 24 小时，过期后删除。
- 图片资产路径逐段拒绝符号链接；目录使用仅当前用户访问权限，清单与 PNG 使用仅当前用户读写权限。

## 升级与恢复点

- `upgrade check` 和 `upgrade plan` 只读检查 Codex Plugin、Persona schema、关系库完整性和 Identity Pack，不创建或迁移用户数据；
- 安全升级先创建恢复点。Persona 和人物参考在复制前后重新计算摘要；关系库使用 SQLite 在线备份接口取得一致性副本；校验失败的暂存目录不会发布为可恢复备份；
- 恢复点只收录当前 Codex 的 Persona、关系数据库和 `private/images` 中的身份资产。短期成图目录、图片回执、Hook 健康回执、审核进度、授权、事件作业、安装收据和锁文件不进入恢复点；这些系统回执失效时只要求重新验证，不要求重传人物参考；
- 旧 schema 的验证在恢复副本上运行。Persona 版本 1、2 只试读；关系库版本 1 在副本中按现有事务迁移逻辑试跑。验证副本随后删除，正式数据不在升级命令中原地迁移；
- Plugin 切换前另存当前 Codex 程序缓存并逐文件校验。这个程序快照不包含 Persona、关系或图片；
- 新 Plugin 切换后的即时健康检查失败时，只还原旧程序缓存。升级器不会用恢复点覆盖当前用户数据；
- `backup recover-copy` 只允许写入全新目录，目标已存在、位于正式数据目录内、包含符号链接或备份摘要不一致时拒绝；
- 安装收据只记录宿主、Plugin 版本、Marketplace 名称和来源类型，不保存仓库路径、用户目录或 Marketplace 的私有来源值；
- 恢复点和程序快照当前不自动清理。删除策略尚未提供前，程序不会把用户恢复能力当缓存回收。

## 查看与导出

默认关系导出仅包含：

- 数据格式版本；
- `relationship_id`；
- 熟悉度、信任度、亲近度；
- 修订号和更新时间；
- 明确列出的排除项。

默认不导出事件明细、来源宿主、会话作用域、聊天文字、Provider 凭据、参考图路径或生成资产。未来若提供“完整诊断导出”，必须单独确认，并在生成前预览包含项。

## 重置、删除与卸载

- “重置关系”删除指定关系的状态、事件和当前气氛，不影响人格配置或其他关系。
- “清除本地关系数据”删除产品控制范围内的数据库主文件及其 WAL、SHM 和 rollback journal 边车文件。
- 人格配置、参考资产和生成资产应作为独立可选项删除，不能因为卸载 Plugin 或 Skill 就默认删除用户内容。
- 卸载时应让用户选择“只卸载程序”或“同时清除本地数据”；当前安装器尚未提供自动卸载流程。

删除承诺只适用于产品控制范围内的当前本地文件，不等于安全擦除磁盘，也无法删除操作系统备份、文件系统快照、用户自行复制的导出包、宿主日志或 Provider 侧留存。若涉及高敏感内容，用户还需按操作系统和 Provider 的规则处理这些副本。

## 图片资产

`0.7.0-dev.6` 的 Codex 面板上传、聊天候选确认与跨任务参考图复用同一个最小资产库，但不调用独立 API 执行器，也不创建图片付费授权。OpenClaw 与 Hermes 的既有严格模式仍使用各自隔离的同类资产库。资产库不是图库：

- 面板入口只接收浏览器当次选择并转换的 PNG 字节，要求用户确认成年与图片使用权，不接收路径。Codex 聊天入口只允许暂存当前任务图片工具回执中出现的 `CODEX_HOME/generated_images` PNG；任务、路径或内容哈希不一致，文件被替换，回执过期或重复使用时都拒绝；
- 严格校验签名、分块长度、CRC、像素格式、像素数量和实际解码大小；
- 保存前重写为只含 `IHDR`、`IDAT`、`IEND` 的 PNG，移除文本、EXIF、GPS 和其他附加元数据；
- 每个 `profile_id + identity_version` 只有一个候选槽和一个 Identity Pack；候选槽一次只暂存一个角色，新候选替换旧候选，不保留候选历史；
- 原型交给事件型宿主前会生成一个路径唯一的短期快照，避免另一会话覆盖候选槽时改变已交付内容；该快照收到明确回执后删除，否则按一小时上限清理；
- Identity Pack 固定三个角色：必需且唯一的 `primary_face`，以及各至多一张的 `profile_face` 和 `body_shape`。未配置可选角色不是错误；已声明成员缺失或损坏时整包不可用；
- Pack 清单只保存角色、不透明 ID、内容哈希、MIME、尺寸、来源、时间和修订号，不保存提示词、聊天、响应正文或真实路径；成员文件名由经过校验的 `reference_id` 推导；
- 人格配置仍只保存主脸的一条不透明 `reference_id`；侧脸和体型属于同一身份版本的私有资产，不扩充 Persona schema；
- 新 Codex 任务开始时，Runtime 用主脸 `reference_id + profile_id + identity_version` 解析唯一身份包；主脸、角色、版本、清单或任一声明成员不匹配时停止生图，不返回另一张脸；
- 旧版完整的 `selected.png + selected.json` 在没有 Pack 新布局痕迹时只读适配为单主脸包，不会因为状态查询写入迁移文件；用户明确确认首张补充参考时才物化 Pack 清单；
- 解析后的绝对路径只进入本次 Codex 私有开发者上下文。Runtime 要求普通场景只用主脸，侧脸或全身场景最多再加入一张对应补充；路径不写入普通回答、关系库、面板 API 或导出。真实图片工具是否实际接收所选输入仍需端到端验收；
- 日常成图保存在当前任务或会话绑定的短期目录，明确附件回执后立即删除；没有回执的 `delivery_unknown` 成图不自动重投，在后续启动时按一小时上限清理；
- 候选与参考图不会因为卸载 Plugin 或 Skill 自动删除，避免程序卸载误删用户已确认身份。

主脸资产写入与 Persona 引用更新跨两个独立文件边界，无法形成单一事务。执行顺序先写资产、保留候选，再更新配置：若能重新读取 Persona 并明确证明主脸没有绑定，程序会在严格核对“修订号 1、只有该主脸、候选槽未变化”后还原成同一个候选，并返回新的 `retry_profile_version`；如果无法判断 Persona 是否已经提交，则同时保留 Pack 与候选，绝不做破坏性回滚，等恢复读取后用同一候选重确认。成功后才清理候选槽。进程在两个步骤之间崩溃，或回滚本身遭遇文件系统故障时，仍可能留下未绑定资产，但绝不会自动启用。补充成员先写不可变文件、最后原子替换 Pack 清单；进程崩溃最多留下未被清单引用的孤儿成员，Runtime 不扫描或启用它。后续清理工具需要显式列出并让用户确认。

## 日志与崩溃信息

默认日志允许记录版本、状态代码、匿名任务 ID、耗时和能力判断；禁止记录聊天正文、完整提示词、参考图内容或路径、联系人、凭据和授权头。崩溃报告若无法保证脱敏，应默认关闭或只保存在本机，并由用户主动导出。
