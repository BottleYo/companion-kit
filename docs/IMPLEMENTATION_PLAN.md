# Companion Kit 阶段 0–1 实施计划

## 目标

本阶段把现有 `0.2.0` 示例收敛为可独立发布的干净项目，并冻结后续真实生图与宿主适配所依赖的公共协议。完成后仍不会发起付费图片请求、读取宿主私人资料或发送外部消息。

## 已批准边界

- 支持 Codex、OpenClaw、Hermes、Claude 四种可选宿主；任一宿主都可独立安装。
- 公共核心只包含通用人格、关系状态、照片决策和能力契约。
- 任何私人 persona、参考图、生成图、聊天、记忆、账号和凭据均不得进入项目、测试、Git 历史或发行制品。
- Content Studio 仅可作为本机质量对照，不复制代码、数据结构或工作流。
- 图片模型基线为 `gpt-image-2`、高画质和参考图编辑；能力不可证明时关闭照片，不静默降级。
- 长期关系不会因用户闲置衰减；当前氛围是带过期时间的会话状态。

## 本阶段交付

1. 独立 Git 仓库和公开发行允许列表。
2. `schema_version = 2` 的人格配置，兼容读取版本 1。
3. 版本化关系事件、确定性归约器、边界优先级和固定测试向量。
4. Provider 能力证明、路由选择和失败关闭契约。
5. 图片任务状态转换骨架，覆盖生成中、取消和失败终态；真实 job ID、回调幂等和迟到结果由后续执行适配器实现。
6. 本地 SQLite 状态库的事务、幂等、版本检查、导出和产品可控范围删除。
7. 数据生命周期、Provider 和本地 Web 面板威胁模型文档。
8. 工作树与 Git 对象双重隐私扫描。

## 迁移与回滚

- 版本 1 人格配置继续可读；只有显式保存或重新初始化时才写成版本 2。
- SQLite 使用独立 schema 版本；发现更高版本时停止写入，不自动降级。
- 本阶段不改写任何宿主全局配置，不安装真实 Provider，也不迁移现有私人状态。
- 所有新增行为由独立模块提供；发生问题时可以回退到 `0.2.0` 的只读照片规划能力。

## 完成证据

- 新增核心逻辑先有失败测试，再实现。
- 全量单元测试通过；需要监听本机端口的测试在允许 loopback 的普通环境复跑。
- 公开树、Git 对象和构建输入均通过私人标识、密钥、绝对路径、聊天状态和人物媒体检查。
- 独立终审无阻断级问题，或所有阻断问题已修复并复验。
