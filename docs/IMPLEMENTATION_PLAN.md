# Companion Kit 分阶段实施计划（Codex 优先）

## 当前优先级决定

从本计划更新之日起，Codex 是第一产品目标和唯一 P0 宿主。开发顺序不再按四端并行推进：

1. 先让非本机 Codex 用户完成一次安装和面板初始化后，可以自然聊天、直接拍照并继续使用 Codex 原有问题解决能力；
2. 再把已经由 Codex 验证过的轻量 Runtime 和交互契约移植到其他宿主；
3. OpenClaw、Hermes 与 Claude 现有适配继续保留测试和安全修复，但在 Codex 验收前冻结新增功能。

这次调整改变的是实施顺序，不代表删除多宿主目标，也不允许把任一私人 persona、照片、聊天或记忆带入公共项目。

## 总目标

先做成一套在 Codex 中轻量、易安装、易理解并愿意持续使用的虚拟陪伴能力：人格是 Codex 原能力之外的表达层；固定人物照片是可选能力；普通问题仍由 Codex 原有工具解决。Codex 验收后再复用同一公共核心适配其他宿主。公共项目始终不包含私人 persona、照片、聊天、记忆、账号或凭据。

## 已冻结边界

- 支持 Codex、Claude、OpenClaw、Hermes 独立安装，不要求同时使用。
- 多宿主是发行目标，不是当前并行开发要求；Codex 体验验收拥有最高优先级。
- Content Studio 只作为质量与思路参考，不搬运重型工作流或数据模型。
- Codex 只使用内置 `gpt-image-2` 图片能力，计入 Codex 方案用量；不配置 API Key，不选择 Provider。
- OpenClaw 与 Hermes 的独立严格路径仍固定官方 `gpt-image-2`、`high`、`moderation=low` 与参考图编辑；不能证明时关闭，不静默降级。
- Codex 照片意图直接进入宿主内置生图；事件型宿主的照片意图仍不等于额外 API 付费授权。
- 只处理成年人或虚构成年人物；用户可在面板亲手选择或在 Codex 当前任务提供有权使用的参考。面板不扫描照片目录、不接收任意路径，项目不得在未获授权时复刻真人。
- 关系是多维状态而非单一等级；长期关系不因闲置自动衰减，短期气氛有 TTL。

## 阶段 0–1：公共核心与关系契约（已完成）

- 干净独立仓库、四宿主安装器和本地初始化面板；
- 四套通用人格模板与版本化配置；
- 三维关系、短期气氛、确定性归约、事务、幂等、迁移与导出；
- 照片意图、纯 Kernel、Provider 路由与任务状态骨架；
- 工作树和全部 Git 对象隐私扫描。

## 阶段 2：图片技术探索（已完成，Codex 决策已修订）

### Codex 内置生图

- 无需 Companion Kit API Key；
- 使用 Codex 当前任务图片能力；
- 人物原型、日常照片和参考图编辑统一走宿主能力；
- 结果只在当前任务显示，不外发 IM。

### 独立 API 技术流程

- 固定官方 Image API、`gpt-image-2`、`high`、`moderation=low`、PNG、单张输出；
- 新身份使用 `generations`，固定后使用唯一参考图 `edits`；
- `OPENAI_API_KEY` 只读当前进程环境；
- 十分钟、摘要绑定、单次消费的付费授权；
- 只保留一个候选槽和一张身份参考，不形成图库；
- PNG 实际解码校验与元数据清理；
- 当前任务短期成图、投递后删除、超时清理。

这套独立 API 代码继续服务 OpenClaw / Hermes 严格适配和测试，不再作为 Codex 产品路径。Codex 的旧 `photo prepare/run` API 生图入口会明确拒绝执行，不能再引导用户配置 Key；`identity stage-native/confirm` 只负责保存 Codex 已生成并经用户确认的主脸或补充候选，不发起图片请求。

### 验收

- Codex 状态只展示内置生图，并明确 `api_key_required = false`；
- Codex 旧 API 命令在联网和创建授权前明确停止；
- 测试传输证明请求固定官方端点、模型、画质和单次调用；
- 同一授权不能重复消费，原文或参考变化后失效；
- 原型确认后配置只保存一个不透明参考 ID；
- 日常照片使用参考编辑，投递确认后短期文件删除；
- 陪伴消息不展示内部提示、Router、Provider、轮询或本地路径；
- 全量测试、插件/Skill 校验、隐私扫描和独立终审通过。

## 阶段 3：事件型宿主适配（技术底座已完成，停止扩展）

### 已实现

- OpenClaw 原生快速模式精确请求 `openai/gpt-image-2/high` 与 `openai.moderation=low`，但诚实标为 `host_managed`；异步回原会话和补缺由宿主独占。
- OpenClaw 与 Hermes 严格模式复用官方 direct API、PNG 清洗与唯一参考图逻辑，不复用 Codex 的本地附件语义。
- 人格、授权、图片和事件作业按宿主默认隔离，不读取或迁移私人宿主配置。
- 事件作业按首次入站事件去重；付费确认可跨下一条事件继续，同一生成和 handoff 都只能 claim 一次。
- 最终投递只允许当前回复：OpenClaw 当前媒体工具不传任意目标；Hermes 只在当前响应使用 `MEDIA:` 交给 Gateway。
- 缺少宿主媒体回执时进入 `delivery_unknown`，不声称已送达、不自动重投，短期成图按 TTL 清理。
- 各宿主 CLI 与数据目录仍然独立；Codex 当前以 Plugin UI 为正式入口，旧本地面板只保留升级兼容，不作为产品路径，也不读取或写入其他宿主 Persona。

### 已完成的验收边界

- 隔离假 Provider 已覆盖原型、身份确认、参考编辑、当前会话 handoff、回执清理和重复执行拒绝。
- 没有真实 `OPENAI_API_KEY`，因此未进行付费图片调用。
- 不在开发验收中向真实外部聊天发送媒体；宿主端真实回执仍需用户在非私人测试会话中单独验收。

上述能力作为兼容底座保留。在 Codex P0 验收完成前，不继续增加外部 IM、后台投递、Claude 图片执行或新的宿主差异逻辑。

## 阶段 4：Codex 自然体验闭环（当前 P0）

当前进度：`0.9.0-dev.1` 已加入轻量 Daily Look。每天第一次聊到 OOTD 或拍人物照片时才安排穿搭，同一天保持主题；面板可以换一套、微调、记住偏好、暂停或恢复。只有真实照片成功后才确认或替换当天主题。既有 Plugin UI、任务隔离、Identity Pack、PhotoMoment、图片保护和安全升级继续复用。自动关系事件与跨机器 Codex 人工验收仍未完成。

### 4.1 一次性初始化

- Codex Plugin UI 允许一句话描述或可选模板，自动补全称呼、性格、说话方式、背景、任务风格和通用外观；用户可以随时重新调整；
- 形象身份不是初始化必填项；保存 Persona 后可以在 UI 直接选择、预览并确认一张参考图，也可以跳过；Codex 不出现 Provider、API Key 或图片模式选择；
- 已固定的主脸可以在面板显式更换；确认前旧身份继续生效，确认后切换到下一身份版本，并完整保留 Persona、关系、历史与旧身份包；
- 用户之后第一次需要固定形象时，仍可在 Codex 对话中直接用内置生图生成、预览并确认原型；
- UI 分开显示 Plugin、Hook、Persona、主脸和陪伴任务状态，不能把安装成功当作运行就绪；
- 配置需要调整时回到 Plugin UI 处理，不在日常聊天中讲解模型、端点、参数或命令；
- 为新手提供推荐默认值，高级选项默认折叠。

### 4.2 Codex 接入边界

- Codex 正常路径改为 Plugin + 本地轻量 Runtime，而不是以 Skill 作为每轮入口；
- `SessionStart` 在每个新任务只写健康回执；只有用户明确绑定的任务才注入 Persona 与关系投影；未绑定任务默认零 Persona 输出；
- 任务绑定只保存本机 HMAC，不保存原始任务 ID 或聊天正文；单次照片请求不自动绑定任务；
- Plugin 安装、用户审核确认、Hook 实际运行和 Persona/主脸加载分别建模；不读取或写入 Codex `trusted_hash`，只由用户在 `/hooks` 完成安全审核；
- `SessionStart`、`UserPromptSubmit`、图片专用 `PreToolUse` 与 `PostToolUse` 组成同一 Hook bundle；`SessionStart` 只证明 Hook 运行，`companion_context` 才证明绑定任务加载了当前 Persona，`PostToolUse` 在第一次真实图片后单独验证；
- 使用最小本地命令提供候选暂存、角色确认和参考包状态，真实生图继续由 Codex 内置工具完成；聊天入口候选必须同时位于 Codex `generated_images` 且拥有当前任务图片工具的单次回执，面板入口只接收用户当次选择并清洗的图片字节；主脸确认后才允许逐张补充侧脸或体型；
- Codex 的配置诊断改走 Plugin UI 或 CLI；`$virtual-companion` 只保留给其他宿主兼容，不进入 Codex Plugin；
- 人格只改变对用户的表达方式，不替代 Codex 的任务规划、代码能力、事实标准和安全规则。
- 陪伴任务常驻上下文只保留 Persona、关系分寸和任务质量防火墙，总长不超过 1400 字符；身份路径、照片规则、今日穿搭和候选命令只在人物照片回合按需加载，总长不超过 3600 字符。

### 4.3 自然聊天与关系

- 只有已绑定任务的普通闲聊以人物身份回应；未绑定任务保持普通 Codex。人物回复不复述模板标签、Hook 或加载过程；
- 关系投影自动影响闲聊语气、主动程度和允许的照片亲密上限，不把数值或等级展示给用户；
- 关系状态保持多维和事件化，不能因为单条消息线性升级，也不能影响问题解决的正确性；
- 任务型请求继续使用 Codex 原能力，只在开场、解释和交付语气中体现人物特点。

### 4.4 一轮完成照片请求

- 初始化就绪后，用户只说“拍张照片给我”时，由人物结合人格、关系、当前对话和最近题材自行选择合理场景；
- 用户给出明确场景时直接执行，不再追问穿着、动作、模式、固定形象或 Provider；
- 未固定脸时自然提供上传参考、描述生成或 Persona 自定三种选择；候选必须先展示并明确确认；
- 已固定脸时按场景从同一私有 Identity Pack 选择参考：普通照片只用主脸，侧脸或全身场景最多加入一张对应补充，始终不超过两张；
- 普通新拍无论当前任务还是新任务都不得沿用上一张生成图；只有用户明确编辑上一张时，才允许加入同一任务内可验证的目标图，并始终同时带主脸；
- 身份参考只锁面部身份和稳定体型特征，不锁发型、表情、妆容、服饰、姿势、镜头和场景；
- 最近四次成功照片只保存受控 PhotoMoment 枚举，用于让新拍至少改变两项画面轴，并优先打开发型或表情；图片结果和随后的文字使用同一个 Moment，文案要接住画面细节和当前对话；
- 每日 OOTD 使用结构化 Daily Look，不调用额外模型或图片工具；用户本张明确要求高于当天主题，关系亲近不自动改变衣服暴露程度；
- 未配置可选补充时继续用主脸；已声明成员或 Pack 无法安全解析时整包停止，不静默生成新脸；明显漂移时只在用户明确要求后使用同一组参考重试，不做隐藏试拍；
- Codex 不做 API 费用或 Provider 配置。只有内置生图不可用、额度耗尽或请求越界时才打断，并提供一句自然说明；
- 一次用户请求只产生一次图片执行和一次自然配图回复，不播报 Skill、Router、Provider、API、计划编号、后台状态或运行秒数；
- Codex 自身的 `Worked for` 和折叠工具轨迹属于宿主界面，项目不承诺隐藏，但必须消除由多轮询问造成的额外等待。

### 4.5 P0 验收脚本

在一台未参与开发的 Codex 环境中完成安装和 Plugin UI 初始化，然后分别用普通任务与陪伴任务验证：

1. 普通任务不加载 Persona；用户无需输入 `$virtual-companion`，只用自然语言明确绑定陪伴任务；
2. “你长什么样”得到简短、第一人称、符合已确认形象的自然回答，不输出外貌规格表；
3. “拍张照片给我”在同一轮直接返回符合关系边界的照片和自然短句，不要求用户编写提示词；
4. 明确指定场景后直接拍摄，不再次询问模式、固定身份或 API 费用；
5. “帮我检查这个项目为什么测试失败”仍能完整使用 Codex 工具并给出可靠结果；
6. 连续聊天不会重复初始化，不暴露内部技术状态；
7. 新任务能够重新加载同一人物、同一身份版本的参考包和关系投影，且不读取任何现有私人 persona 或聊天历史；真实图片工具调用中必须人工确认所选 1–2 张参考参数确实生效；
8. 同一天的照片沿用主题但不会锁死发型、表情和妆容；换一套只在真实照片成功后提交，升级后 Daily Look 仍在。
8. 普通、侧脸与全身场景分别选到主脸、主脸加侧脸、主脸加体型；不会把三张同时注入；
9. 改变发型、妆容、服饰和场景时仍保持同一脸部身份；任一已声明参考缺失时不会换脸继续生成。
10. 连续生成多张时不会只换背景和衣服；普通新拍不把上一张图片作为参考，明确编辑才例外。
11. 图片后的文字与当张场景、动作和表情一致，能自然留下下一句，不播报内部状态，也不只问“喜欢吗”。

只有上述流程通过跨机器人工验收，Codex 才从 Developer Preview 进入普通用户内测。

## 阶段 5：Codex 内测与产品化

- 完成 Plugin UI 在 macOS 与 Windows Codex 的真实渲染和交互验收；
- 继续简化跨机器安装；本地 Marketplace 已有确认式升级，后续补 Git 来源更新、快照保留策略和卸载；
- 覆盖初始化中断、Codex 内置图片不可用、图片失败和配置损坏的恢复路径；
- 完成本地隐私检查、发行包检查和普通用户可理解的错误信息；
- 用真实新用户验证首次成功时间、照片请求轮数和继续聊天意愿。

## 阶段 6：其他宿主适配（Codex 验收后）

- 把 Codex 已验证的 Runtime 公共接口分别接入 OpenClaw、Hermes 与 Claude；
- 保留每个宿主的会话、凭据、照片投递和数据目录隔离；
- 在 Claude 明确具备当前任务图片工具和附件契约后再接入真实图片执行；
- 逐端进行真实但非私人测试，不因 Codex 成功就假定其他宿主行为等价；
- Codex Plugin UI 继续保持轻量，不发展为 Content Studio 或通用内容生产平台。

## 回滚原则

- 每个宿主和图片模式都是独立适配器；失败时可以关闭该能力，不影响人格聊天与任务解决。
- 不迁移或改写现有私人宿主状态。
- 发现更高配置或数据库版本时停止写入，不猜测降级。
- 卸载程序默认不删除人格、关系或已确认参考图；数据删除必须单独确认。
