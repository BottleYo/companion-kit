# 开发者内测指南

## 当前定位

`0.9.0-dev.4` 是 Codex-first Developer Preview。普通任务不受影响，用户挑一个任务作为陪伴空间；需要照片时使用同一人物身份，同一天还能自然延续一套 OOTD。

这一版可以验证：

- Codex Plugin UI 能在任务内打开，不启动独立 App Server；
- 用一句话或模板保存 Persona，再次保存时保留已确认身份；
- 在面板选择、预览、确认或更换主脸；
- `/hooks` 人工审核、`SessionStart` 运行回执和 Persona 实际加载回执互相独立；
- 只有用户明确绑定的任务才加载 Persona，普通任务保持 Codex 原样；
- 普通任务可以请求一次人物照片，但不会因此自动绑定；
- 照片回合使用 Codex 内置图片能力，不需要 API Key；
- 每日 OOTD 只在第一次聊到穿搭或拍照时生成，不增加图片调用；
- 人物面板可以保存当前 Persona 的私有造型方向、表现程度、标志性元素和禁区，不污染公共模板；
- 每日造型会同时给出服装、配饰、发型、妆容、神态和“今天的小心思”，配图话术再结合 Persona 与关系分寸；
- 问完今日 OOTD 后可以用“拍吧”续拍，孤立短句不会劫持普通任务；
- 升级前创建用户恢复点和旧 Plugin 程序快照。

暂时不能承诺：关系会从真实聊天自动变化；所有 Codex 版本的 Plugin UI 和图片工具契约完全相同；参考图能让生成模型达到像素级零漂移；OpenClaw、Hermes 与 Claude 同步获得本轮能力。

## 推荐验收顺序

### 1. 安装和 Hook

1. 在隔离环境安装 Plugin，不要单独安装 `skills/virtual-companion`。
2. 安装后先确认 Codex 能识别 Companion Kit，但不要把“已安装”当作“可使用”。
3. 输入 `/hooks`，本人审核 `SessionStart`、`UserPromptSubmit`、图片专用 `PreToolUse` 和 `PostToolUse`。
4. 完全退出并重开 Codex，新建一个普通任务。
5. 打开人物面板。此时 `SessionStart` 应已验证，但没有 Persona 或没有陪伴任务时不能显示完整就绪。

不得写入 `trusted_hash`，不得使用 `--dangerously-bypass-hook-trust`，也不得修改用户全局 `AGENTS.md`。

### 2. 人物面板

1. 用“高冷御姐，成熟自信，做事利落”这类一句话创建 Persona，检查系统是否自动补出协调设定。
2. 再选择一个模板保存，确认模板只是起点，用户描述仍能生效。
3. 上传一张不含私人信息的成年虚构人物测试图。未勾选图片权利确认时，按钮必须不可用。
4. 确认主脸后检查面板只显示状态，不返回图片内容、参考 ID 或本机路径。
5. 再换一张测试图。确认前旧脸继续有效；确认后身份版本前进，Persona 和关系文件不被清空。

### 3. 普通任务隔离

在一个从未绑定的普通任务里完成代码排查或分析：

- `SessionStart` 不应输出 Persona；
- 普通回答不应出现人物口吻、关系称呼或照片规则；
- 非图片工具不触发照片 Hook；
- 打开 Plugin UI 之前，不应有“Skill 已启动”一类聊天内容。

然后说“拍张照片给我”。这次可以加载 Persona 和主脸，但任务仍保持未绑定。下一条普通技术问题应回到普通 Codex。

### 4. 陪伴任务

1. 新建任务，说“把这个任务设为陪伴任务”。
2. 面板应显示至少一个陪伴任务，Persona 加载回执变为有效。
3. 闲聊时检查语气自然，不复述人格标签、Hook 或内部状态。
4. 提交一个真实 coding 问题，确认工具选择、代码正确性和测试质量没有下降。
5. 说“退出陪伴任务”，再开新轮检查 Persona 不再加载；Persona、关系和主脸数据仍在。

绑定并拍照写在同一条消息时，当前版本只完成绑定，提示用户下一条再拍，避免图片调用绕过身份保护。

### 5. 连续照片

- 连续拍四张，至少让场景、动作、构图、发型、表情或妆容中的两项发生变化；头部角度、视线和嘴角不能四张都保持同一套；
- 半身、三分之二身和全身照片应保持偏高挑但自然的成年人比例，不出现大头、窄肩、短颈、压缩躯干或超广角造成的头大身小；
- 普通新拍只使用 Identity Pack，不沿用上一张生成图；
- 明确说“把上一张的眼镜换掉”时，才允许编辑同一任务最近一次可验证的人物照片；
- 普通、侧脸和全身场景分别使用主脸、主脸加侧脸、主脸加体型，任何一次最多两张参考；
- 图片后的文字要接住当张画面，不播报生图提示、Router、重连或耗时；
- 任一已登记参考图损坏时停止本次人物生图，不用纯文字捏一个陌生人补位。

Plugin UI 和 Hook 字符串测试不能代替这一步。必须展开真实图片工具调用，确认 `referenced_image_paths` 实际传入。

### 6. 每日 OOTD

1. 打开面板不应自动创建今日穿搭；点“安排今天”后才出现结构化主题。
2. 先设置一句造型方向和一个标志性元素，再安排今天；完整造型应能呼应 Persona，禁区不得出现在方案中。
3. 同一天先问“你今天穿什么”，再拍两张不同场景；核心服装和配色应连续，发型、妆容和神态在今日方向内自然变化，头部角度、视线和嘴角不能机械复制。
4. 说“今天换一套再拍”应在照片成功后替换当天主题；失败或取消时保留旧主题。
5. 说“这张单独穿白衬衫”不应覆盖当天主题；编辑上一张时继续沿用目标图中的服饰。
6. 图片成功后的文字要提到一个实际可见细节，并符合 Persona 和当前关系；低亲密度不能使用恋人式表达，高亲密度也不能把所有 Persona 都写成同一种撒娇口吻。
5. 面板的换一套、微调、记住偏好、暂停和恢复都要明确点击。普通 Coding 任务里讨论 OOTD 功能，不能因此加载 Persona。
6. 在已绑定任务问“今日的 OOTD 是什么”，下一句说“拍吧”；检查照片上下文带入同一 Daily Look 和主脸。换到另一任务、等待超过十分钟或先转去写代码后再单独说“拍吧”，都不应启动人物照片。

### 7. 升级

1. 先安装上一版并创建 Persona、关系状态和主脸。
2. 更新项目代码，执行 `upgrade check` 和 `upgrade apply --confirm`。
3. 核对 Persona、关系库、Identity Pack 和 Daily Look 正式文件没有被覆盖。
4. 检查用户恢复点和旧程序快照都能通过校验。
5. 重新审核新 Hook，重开 Codex；旧任务不应半路加载新版本。
6. 打开 Plugin UI，再次验证 Persona、主脸和陪伴任务状态。

## 结束测试

卸载 Plugin 不会自动删除 Persona、关系或参考图。测试数据确认不再需要后，再单独删除测试用 `COMPANION_HOME`。真实重要 Persona 在删除前先验证恢复点。

反馈可以包含 Codex 版本、安装方式、复现步骤和匿名错误摘要。不要提交 API Key、token、聊天正文、人物照片、任务标识或本机绝对路径。
