# 开发者内测指南

## 当前定位

`0.7.0-dev.3` 是 Codex-first Developer Preview，不是面向普通用户的稳定版本。它适合愿意在测试环境验证初始化、Plugin 安装、安静 Persona、Codex 内置生图和固定脸部身份的开发者。

当前开发主线已经调整为 Codex 优先。普通用户内测暂缓，先用未参与开发的 Codex 环境验证“一次面板初始化，后续自然聊天、直接拍照、继续解决问题”的完整体验。OpenClaw、Hermes 与 Claude 暂时只做现有能力回归和安全修复。

当前可以验证：

- Codex 独立 Persona；其他宿主原有配置不会被面板保存操作修改；
- 一句话 Persona 草稿、可选模板、预览、调整和用户字段保留；
- Codex 完整 Plugin 安装、`SessionStart` Hook 和无 Skill 的自然聊天入口；
- Codex 内置图片生成，不需要 API Key 或 Provider；
- Codex 当前任务图片回执、候选 PNG 暂存、明确确认、唯一身份参考和新任务取回；
- 图片清洗、任务作用域绑定、固定身份参考和失败关闭。

当前不能承诺：

- 关系数值会自动从真实聊天中更新；当前关系核心仍需宿主接线；
- 所有 Codex 版本都使用相同的图片工具名称、回执字段和保存位置；真实契约仍需跨机器验收，匹配不到时身份固定会停止；
- 参考图可以保证像素级不漂移；模型仍可能漂移，只能检测明显变化并重试或停止；
- OpenClaw、Hermes 与 Claude 会获得本轮新能力；本轮不扩展它们；
- 自动升级、自动卸载或无人协助的故障恢复。

## 已经在使用 OpenClaw 或 Hermes 时

可以复用已经安装的程序，但不要直接使用正在进行的私人会话做首次测试。推荐顺序：

1. 优先使用独立的操作系统测试账号、宿主测试实例或专用测试 Bot；
2. 使用非私人测试会话，不导入原有 SOUL、USER、记忆、聊天、照片或凭据；
3. 在启动测试宿主之前，为 Companion Kit 设置独立数据目录；
4. 先执行安装预览，确认目标位置后再应用；
5. 若为 OpenClaw / Hermes 启用严格图片模式，使用单独的低额度 API Key，并监控实际用量；Codex 不配置 Key；
6. OpenClaw/Hermes 的外部发图只在专用测试频道验证，不接生产 IM。

macOS/Linux 可在启动测试宿主的同一个终端中创建临时数据目录：

```bash
COMPANION_TEST_HOME="$(mktemp -d)"
export COMPANION_HOME="$COMPANION_TEST_HOME"
```

从 Dock 或其他桌面入口启动的程序通常不会继承这个终端环境。无法确认环境隔离时，请改用独立测试账号或测试实例，不要冒险指向正在使用的宿主数据。

安装 Skill 本身不会读取现有私人 persona，但全局安装可能让该 Skill 在其他会话中变为可发现状态。应用安装前应记录现有 Skill 状态，并保留可恢复备份。

## 推荐验收顺序

### 第一轮：Codex 初始化与普通任务

- 打开本地管理面板；
- 用一句话描述 Persona，或者选择模板起点；检查自动补全内容并保存；Codex 不应出现图片 Provider 或 API Key 选项；
- 完成安装后在新任务中验证不需要再次输入 Skill 名称；
- 验证普通聊天自然，不复述人格标签或技术状态；
- 验证普通问题仍由 Codex 原有能力完整处理。

当前版本已经实现无 Skill 的会话 Persona 加载。它仍需在未参与开发的 Codex 环境完成安装、Hook 信任、新任务重载和普通问题解决的人工验收。

### 第二轮：Codex 照片闭环

- 不设置 `OPENAI_API_KEY`，确认图片直接计入当前 Codex 方案用量；
- 在 Codex 当前任务用内置生图生成一张虚构成年人候选，或先上传有权使用的参考再生成候选；检查图片工具回执已被同任务 Hook 识别；
- 确认前检查本地状态仍为 `unset`，明确确认后检查状态变为 `locked`；
- 主脸确认后，分别明确提出增强侧脸和全身稳定性，逐张生成并确认 `profile_face` 与 `body_shape` 候选；检查 Persona 仍只保存原主脸 ID，面板只显示“已增强”与角色状态，不返回 ID、哈希或路径；
- 新开任务，先基于主脸生成一张不同发型、服饰或场景的普通照片，再分别测试侧脸和全身场景；
- 展开实际图片工具调用，核对普通场景只带主脸、侧脸场景带主脸加侧脸、全身场景带主脸加体型，且任何场景都没有把三张同时注入；仅看到 Runtime 文本不算通过；
- 核对脸部身份保持稳定，而动态造型没有被参考图机械锁死；
- 暂时移走任一已经登记的私有参考成员，确认整个身份包停止生图而不是忽略损坏成员或生成另一张脸；测试后恢复文件；
- 验证“拍张照片给我”不再要求补充场景、模式或 API 术语；
- 核对没有索要 API Key、选择 Provider 或跨宿主共享状态。

### 第三轮：其他宿主回归（不属于本轮）

- 仅使用测试 Bot 和测试会话；
- 分别验证生成完成、当前会话接管和明确媒体回执；
- 没有明确回执时应保持 `delivery_unknown`，不能声称已发送，也不能自动重投。

## 结束测试与恢复

- Codex 使用 Plugin 管理界面或 `codex plugin remove` 移除 `companion-kit`；其他宿主使用各自的 Skill 管理方式；
- 确认临时数据中没有需要保留的参考图后，将整个测试数据目录移到系统废纸篓；
- 恢复测试前记录的宿主环境和安装状态；
- 不要因为卸载 Plugin 或 Skill 就自动删除非测试人格或图片数据。

当前版本没有自动卸载器，因此每次内测应由能够完成上述恢复操作的人陪同。

## 反馈内容

反馈可以包含宿主名称与版本、安装方式、复现步骤、期望结果、实际状态和匿名错误摘要。不要提交 API Key、token、真实聊天、人物照片、联系人、会话标识或本机绝对路径。
