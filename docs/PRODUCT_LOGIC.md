# Companion Kit 产品逻辑

## 项目目的

Companion Kit 想给 Codex、OpenClaw、Hermes 和 Claude 增加一个轻量的虚拟陪伴层。用户只需要安装一次，在本地面板选好人格和人物形象，之后仍然使用自己熟悉的工具。

陪伴对象可以参与日常聊天，也能继续完成原工具擅长的代码、分析、搜索、写作和文件任务。项目不会另做一套重型内容平台，也不会要求用户同时使用四个宿主。

当前开发只把 Codex 当作 P0。原因很直接。Codex 已经有成熟的任务能力和原生图片能力，最适合先验证“陪伴感”和“解决问题”能不能自然共存。OpenClaw、Hermes 和 Claude 会在 Codex 体验通过以后，分别接入同一套公共核心。

## 四层结构

### 人格配置

人格配置保存称呼、性格倾向、说话习惯、边界和通用外观。内置模板只是容易上手的起点，用户可以在面板里调整。

人格只影响最终表达。它不能改写宿主的安全规则，不能降低事实标准，也不能阻止 Codex 为了完成任务而使用工具。

### 关系状态

关系包含熟悉度、信任度和亲近度三个长期维度，另有带有效期的短期气氛。状态变化由少量结构化事件驱动，同类事件有冷却时间，每天的变化有上限。

这种做法避免了两个常见问题。一条消息不会让关系突然升级，几天没有聊天也不会机械扣分。用户明确表达不适后，短期气氛会先影响语气，后续是否修复则由新的事件决定。

关系投影只影响闲聊的主动程度、亲昵称呼和照片表达上限。它不会影响任务型回答的正确性。

### 图片身份

模板提供文字外观。用户需要固定形象时，Codex 直接用内置图片生成一张虚构成年人原型，不经过 Companion Kit API。用户确认后，项目再把它保存为唯一身份参考。后续照片仍调用 Codex 内置生图，只是带上这张参考图。

身份参考与普通成图分开管理。身份参考可以跨任务继续使用，普通成图只为当前交付短期保存。当前版本不导入任意外部真人照片，也不保存候选历史和照片图库。

### 宿主适配

公共核心不知道照片最后发到哪里。每个宿主自己提供当前任务或当前会话边界。

- Codex 使用 Plugin 加载会话上下文，照片直接调用宿主内置图片能力；下一步通过本地工具接入参考图保存和关系事件。
- OpenClaw 与 Hermes 使用事件型适配，只允许交给当前入站会话。
- Claude 在附件契约明确以前只保留安全计划。

用户安装多个宿主时，各宿主仍然拥有独立配置、关系、授权和图片目录。跨宿主共享以后只能做成用户主动选择的功能。

## Codex 为什么从 Hook 开始

Skill 适合用户明确要求一项专业流程。虚拟陪伴却需要在普通聊天开始前就存在。每次先输入 `$virtual-companion`，人物会立刻变成一个被调用的功能。

Codex Plugin 支持会话生命周期 Hook。当前版本只使用 `SessionStart`，在新任务开始时读取本地人格和已有关系投影，然后作为开发者上下文交给 Codex。

我们有意没有接入 `UserPromptSubmit`。这样本地 Hook 不会接收每一条用户消息，也不会因为人格层增加每轮调用。配置更新后开一个新任务即可重新加载。

Hook 还遵守几个失败边界。

- 没有配置时不输出任何内容。
- 配置损坏时不阻断 Codex。
- 不显示状态消息。
- 不读取聊天转录，不保存用户消息。
- 输出长度有上限，配置中的换行和超长文本会被压平截断。

Codex 会要求用户在安装时查看并信任命令 Hook。这一步不能由项目绕过。信任对象变化后，Codex 会再次要求检查。

## 关系自动变化还缺什么

当前仓库已经有关系归约器和 SQLite 单一状态源。真正的自动变化还需要一层低敏事件提取器。

这层只应提交事件类型、置信度、时间和不透明作用域，不能把聊天正文写进数据库。它还要区分闲聊和任务。用户说“这个测试太难受了”通常是在评价代码，不应该被误判成对陪伴对象不满。

Codex 下一阶段会通过最小本地工具完成两件事。

1. 读取当前关系投影和照片表达上限。
2. 在明确、可信的互动发生后提交一个结构化事件。

低置信度事件会被拒绝。关系变化后，工具返回新的投影供当前任务使用；下一次新任务再由 Hook 读取持久状态。

## 一轮照片体验还缺什么

Codex 当前任务已经可以直接生成图片。现在缺的是一个适合 Codex 自动调用的窄接口，用来保存用户确认的候选，并在新任务中取回参考图。

它需要接收自然照片意图，而不是要求用户输入命令格式。用户没有给场景时，Runtime 根据人格、关系上限和当前对话选一个普通生活场景。用户已经给出场景时直接使用，不再追问模式和参数。

Codex 路径不配置 API Key，也不选择 Provider。只有内置图片能力不可用、使用额度耗尽或请求越界时才打断聊天。工具只返回参考图状态和必要的失败类别，不把内部提示词、路径、计划编号和处理状态交给人物复述。

## 项目保持轻量的方法

- 面板只管理初始化、状态和少量恢复操作。
- 人格使用版本化 TOML，关系使用结构化 SQLite，不建立聊天数据库。
- 图片只保留一张身份参考和短期交付资产。
- 宿主适配器只处理当前宿主真正拥有的能力。
- 诊断 Skill 显式调用，普通 Codex 对话使用 Plugin Runtime。
- Content Studio 等项目可以提供思路，但不会被整体搬入。

## 当前版本的诚实边界

`0.6.0-dev.1` 已经完成 Codex 无 Skill 的会话人格加载、完整 Plugin 安装路径，并统一了 Codex 内置生图路线。它尚未完成从聊天自动写入关系事件，也尚未完成跨任务参考图的自动保存和取回。

因此当前版本可以公开查看和开发者试用，不能宣传成已经完成的虚拟伴侣产品。普通用户内测要等 Codex 的自然拍照、关系事件、跨机器安装和失败恢复都通过人工验收。
